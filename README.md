# InvoicePress · 发票印擎

InvoicePress 是一个面向 Windows 的中文桌面工具，用于把一批 PDF 发票按首页高度配对、排版到单页 A4 PDF，并在人工核对后提交给指定打印机。

应用刻意把“生成文件”和“提交打印”分成两个步骤。生成成功不会自动打印；只有用户在结果区确认文件并点击“打印处理结果”后，应用才会调用 Windows 的 PDF 文件关联程序。

## 适用范围

InvoicePress 适合以下输入：

- 每个 PDF 的第一页就是需要打印的发票；
- 发票主要需要按高度组合，一张 A4 放置两份；
- 操作人员会在打印前核对生成结果；
- Windows 已安装支持 `printto` 的 PDF 阅读器。

当前版本不是通用 PDF 拼版器。它不递归扫描目录、不处理第二页及后续页面，也不会根据内容、纸张方向或页面宽度自动选择版式。

## 快速开始

### 环境要求

- Windows 桌面环境；
- .NET 10 运行环境；开发和构建需要 .NET 10 SDK；
- 如需打印：系统中存在可用打印机，并已为 PDF 文件注册支持 `printto` 的关联程序。

### 构建与运行

```bash
dotnet restore
dotnet build InvoicePress.csproj
dotnet run --project InvoicePress.csproj
```

项目目标框架是 `net10.0-windows`，不承诺在非 Windows 桌面环境运行。

### 操作流程

1. 选择源 PDF 目录。
2. 选择已经存在的输出目录。源目录和输出目录不能是同一路径。
3. 点击“开始合并”，等待扫描、配对和文件生成结束。
4. 在“合并结果”中核对每组源文件、单独成页项、输出文件名和失败原因。
5. 如需打印，选择打印机并点击“打印处理结果”。应用只会提交本轮成功生成的文件。
6. 通过状态条和“处理日志”查看进度；运行中可点击“停止任务”。

结果清单和日志分别位于固定高度的滚动区中；日志仅保留最近 200 条，可手动清空。

## 处理规则

### 1. 扫描与元数据

- 只扫描源目录第一层中文件扩展名为 `.pdf` 的文件，扩展名匹配不区分大小写。
- 子目录不会被扫描。
- 每个 PDF 只读取首页的宽度和高度。无页面、尺寸无效、损坏或无法读取的文件会记录失败原因并跳过，其余文件继续处理。这类读取失败不会生成结果卡片，也不计入结果区的失败统计，应以日志为准。
- 输出只绘制各输入 PDF 的首页；多页 PDF 的第二页及后续页面不会进入输出。

### 2. 配对

有效 PDF 先按首页高度从高到低排列；高度相同时按完整路径进行不区分大小写的排序，以保持结果稳定。

- 有效文件数为奇数时，最高的一份先安排为单独 A4 成页。
- 其余文件每轮尝试“当前最高 + 当前最低”。
- 若两份在允许的缩放范围内可用，则形成一组。
- 若不可用，较高的一份改为单独成页，较低的一份放回队列，与下一份较高文件继续尝试。
- 回退后若只剩一份，也会安排为单独成页。

### 3. 缩放与 A4 排版

输出页固定为 595 × 842 磅的 A4 页面。

对于配对项，缩放比例在 70%～100% 之间按 1 个百分点搜索。算法优先让较短发票保留更大的比例，再为较高发票寻找尽可能大的比例。可用性判断只检查两份发票缩放后的总高度是否不超过 A4 高度：

```text
第一份首页高度 × 第一比例 + 第二份首页高度 × 第二比例 ≤ 842 磅
```

较高发票贴齐页面顶部，较短发票贴齐页面底部；两者水平居中，不额外保留固定间距。单独成页项固定按 70% 缩放，贴齐顶部并水平居中。

重要限制：当前算法不使用页面宽度判断是否适合 A4，也不会旋转页面或继续缩小到 70% 以下。因此过宽内容可能越出 A4 左右边界，过高的单独成页内容也可能越出底部。正式打印前应检查生成结果。

## 输出文件与替换语义

- 配对输出名：`<较高文件名>_<较短文件名>.pdf`；
- 单独成页输出名：`single_<源文件名>.pdf`；
- 名称中的源文件名不包含原 `.pdf` 扩展名。

每个输出先写入输出目录中的随机临时文件。只有生成成功后，应用才会把临时文件移动到最终路径，并覆盖该目录中已有的同名历史输出；生成失败时不会主动替换对应的历史文件。

同一批次内如果不同组合得到相同候选名，后续文件会依次使用 `_2`、`_3` 等后缀。批次内比较不区分大小写。这个编号只解决本批次内部的重名：如果最终选定的带编号名称在输出目录中已经存在，它仍会被成功的新结果覆盖。

应用不会删除源文件，也不会清理输出目录中的其他文件。临时文件会在每项处理结束时尝试删除；若操作系统拒绝清理，隐藏的 `.tmp.pdf` 文件可能残留。

## 失败与取消语义

### 单项失败

- 元数据读取失败：跳过该输入，继续处理其他有效 PDF；
- 配对文件生成失败：记录该组失败并继续下一项，不会自动把这两份输入改成两个单独 A4 文件；
- 单独成页生成失败：记录失败并继续下一项；
- 打印文件不存在或关联程序启动失败：记录该文件的提交失败并继续后续文件。

结果区只把成功生成且仍属于本轮结果的文件列入可打印集合。日志会尽可能显示底层服务提供的错误信息。目录枚举等批次级异常会终止本轮任务，并在状态区显示失败。

### 取消合并

“停止任务”通过取消令牌协作停止，通常在当前文件操作响应取消或进入下一检查点时生效，不保证瞬时中断：

- 当前临时文件会尝试清理；
- 已经移动到最终路径的输出不会回滚或删除；
- 尚未替换的历史同名输出保持原状；
- 因为被取消的批次不返回完整结果，已经生成的部分文件不会重新填入本轮结果清单，但仍可能存在于输出目录中。

再次开始合并会清空界面中的上一轮结果清单，但不会清空输出目录。

### 取消打印

取消会阻止后续尚未提交的文件继续处理，但不能撤回已经交给 PDF 关联程序的请求。若需要取消已经进入系统或应用队列的作业，应在 PDF 阅读器或 Windows 打印队列中操作。

## 打印边界

打印服务通过 Windows Shell 对每个 PDF 执行 `printto`，并把所选打印机名称传给系统关联的 PDF 程序。因此：

- “已提交打印”只表示 Windows 接受了启动关联程序的请求并返回了进程；
- 它不表示关联程序已经接受打印参数、打印机队列已经完成，也不表示已经物理出纸；
- 静默打印、弹窗行为、参数兼容性和进程生命周期取决于本机 PDF 阅读器；
- 应用不轮询打印队列，也不追踪纸张、墨粉、卡纸或最终作业状态。

## 技术与架构

| 层次 | 主要实现 | 职责 |
| :--- | :--- | :--- |
| UI | Avalonia UI 12.0.4 | Windows 工作台、状态、结果和日志展示 |
| 状态与命令 | CommunityToolkit.Mvvm 8.4.2 | 目录选择、合并/打印/取消命令及界面状态 |
| 编排 | `ProcessingOrchestrator` | 扫描、失败隔离、临时文件、输出替换、进度与打印批次 |
| PDF 规则 | `PdfMetadataService`、`PdfPairMatchingService`、`ScaleCalculationService` | 首页读取、高低配对和缩放计算 |
| PDF 输出 | PdfSharp 6.2.4、`PdfMergingService` | 把首页绘制到 A4 输出页 |
| 打印 | `PdfPrintingService` | 枚举 Windows 打印机并调用 Shell `printto` |
| 依赖注入 | Microsoft.Extensions.DependencyInjection 10.0.8 | 服务和 ViewModel 生命周期 |

```text
InvoicePress/
├── Assets/                        # 图标与应用资源
├── Models/                        # 处理计划、结果与日志模型
├── Services/
│   ├── Abstractions/              # 服务契约
│   └── Implementations/           # 元数据、配对、合并、打印和编排
├── Utils/                         # PDF 常量与安全文件对话框
├── ViewModels/                    # 主窗口状态和命令
├── Views/                         # 主窗口及工作台组件
├── tests/InvoicePress.Tests/      # 规则、编排和 ViewModel 测试
├── App.axaml                      # 全局资源与控件样式
├── App.axaml.cs                   # 依赖注入与应用生命周期
├── InvoicePress.csproj
└── README.md
```

## 开发与验证

运行自动化测试：

```bash
dotnet test tests/InvoicePress.Tests/InvoicePress.Tests.csproj --configuration Release
```

提交前建议运行：

```bash
dotnet format InvoicePress.csproj --verify-no-changes --no-restore
dotnet build InvoicePress.csproj --configuration Release --no-restore
git diff --check
```

现有自动化测试主要使用测试替身验证配对、缩放、输出命名、失败传播及 ViewModel 的可打印文件选择，不能替代真实 PdfSharp 输出或 Windows 实机验证。涉及发布时，仍需在目标机器上检查窗口布局、真实和多页 PDF 渲染、页面越界情况、打印机枚举、关联程序的 `printto` 行为、打印队列和物理出纸。
